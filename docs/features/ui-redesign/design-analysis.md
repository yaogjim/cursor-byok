## 1. 现状诊断

对照当前总览页截图与 `global.css` / `Home.vue` / `HomeMetricsCard.vue` 的实现，问题集中在七处，且都不是功能问题：

| # | 问题 | 具体表现 | 根因 |
|---|------|---------|------|
| 1 | 绿色成了底色，不再是信号 | 主色 `#10B981` 同时用于按钮、KPI 数字、命中率环、命中率曲线、状态点、tab 下划线；圆环 92.22% 是最大面积的强调色 | 主题只定义了「主色」，没有「强调分级」，组件只能各自拿主色 |
| 2 | 所有信息等权 | 服务卡、KPI、图表都是白卡 + 1px 边 + 微阴影，圆环、大数字、图表同等视觉权重 | 缺少「主叙事区 / 辅助区」的布局层级，只有卡片平铺 |
| 3 | 顶栏信息噪音 | `1 已接入`、`37` 徽标与导航标签同级；右侧「状态更新于 10:26」又占一格 | 导航承担了状态展示，状态没有独立归宿 |
| 4 | 数字与标签脱节 | KPI 标签 11px 灰字，数字 32px 天字重；中间没有过渡，也没有趋势、口径提示 | 只有「值」，没有「值 + 变化 + 口径」的信息组 |
| 5 | 图表拥挤 | 五条线全实线，网格横竖都有，右轴百分比与左轴 token 挤在一起，图例只是一行色块 | 图表配置是「能看」，没有做视觉分层（主次线、区域填充、悬停卡） |
| 6 | 页脚与页内重复 | 页脚显示代理状态和版本检查，与页内服务卡信息重叠 | 状态信息没有单一归宿 |
| 7 | 令牌不落在栅格上 | `--radius-card: 13px`，字号 11/14/18/24/32 五档跳变，卡片内边距 16px 但页边距 22px | 令牌体系是逐步加出来的，没有 8pt 约束 |

一句话总结：**现在的界面是「表单堆叠成卡片」，不是「信息有层级的仪表盘」**。用户看到的第一眼应该是「服务是否正常 + 这次会话表现如何」，现在第一眼是「五块一样重的白色矩形」。

## 2. 设计原则（三方向共用）

1. **一屏一个主角**：总览的主角是「服务运行状态 + 本次会话价值」；KPI 和图表是支撑层，视觉权重必须递减。
2. **强调色分级**：主色只用于「主操作」「运行中」「关键价值数字」三处；其余一律中性色或图表色板。命中率环、曲线不用主色。
3. **卡片少而准**：容器只用于真正需要独立边界的块（趋势图、侧栏分组）；服务状态用细线分隔的横条，不用卡片。
4. **数字先行**：所有数字等宽字体 + `tabular-nums`，单位缩小并弱化，口径说明紧跟数字下方，而不是塞进 tooltip 才看得到。
5. **弱化装饰**：去掉卡片阴影堆叠，嵌套层级 ≤ 2；分隔用细线，不用双边框 + 底色 + 阴影三重叠加。
6. **状态四档统一**：运行中（主色）、警告（琥珀）、错误（砖红）、停用（灰）。删除 info 蓝的第五种状态语义。

## 3. 三个方向

### 方向 A · Ledger（深色控制台）
- **语言**：近黑底 `#0E0F11` + 左侧 60px 图标轨道 + 细线分区，数字用 SF Mono，绿色只做「运行中」和「价值」两处信号。
- **适合**：长时间挂后台、开发者主力场景；深色降低大面积白底的疲劳。
- **代价**：需要维护一套完整的深色语义令牌（现有深色模式只是变量替换，没有单独校验过对比度）；截图分享、录屏时观感偏「工具」。
- **风险**：Wails 桌面壳在深色下窗口阴影、Dock 过渡需要额外处理。

### 方向 B · Paper（浅色编辑部报表）
- **语言**：米白纸底 `#F6F5F1` + 墨色文字 + 细线分隔 + 超大等宽 Hero 数字，几乎没有卡片，靠留白和细线组织。
- **适合**：数据阅读、截图汇报；差异化最强，不会和任何「Tailwind 后台模板」撞脸。
- **代价**：信息密度低，窗口变窄时排版掉档明显；对字号和间距精度要求高，实现时容错小。
- **采纳（2026-11-18）**：本方向为唯一落地方向。落地规则见 §7「B 的落地设计规则」。

### 方向 C · Console（精致卡片控制台）
- **语言**：浅灰绿底 `#F4F6F5` + 白色 16px 圆角卡片 + 柔和投影 + 胶囊导航；一张深绿色「招牌卡」承载命中率，其余三张 KPI 卡片带 sparkline。
- **适合**：现有实现的自然演进——结构、组件、状态逻辑都不用改，只换令牌和布局；macOS 原生应用质感（Raycast / Linear / Arc 一路的视觉语言）。
- **代价**：需要新增 sparkline、深色招牌卡、胶囊导航三个视觉件；sparkline 需要真实时间序列，现有 `homeMetricsReport` 已能提供小时序列，可作为数据源。
- **未被采纳的原因（2026-11-18 决策）**：结构最接近现状、迁移成本最低，但读起来像监控面板，信息密度优先于阅读舒适度，与用户偏好的「人性化」取向冲突。其中可回收的工程结论——招牌卡、sparkline、胶囊控件——作为 B 的可选组件保留。

## 4. 总览页信息架构（推荐顺序）

以方向 B 落地：

```
┌─ 顶栏：品牌 · 下划线式导航 · [状态时间] [刷新] [重置统计]
├─ 服务行：Cursor 代理 / Gateway 两栏细线分隔，状态点 + 地址 + 内联操作
├─ Hero：超大字重命中率 + 口径注释（复用率 / 命中绝对值）+ 右侧会话价值
├─ KPI 条：对话轮次｜LLM 调用｜Token 消耗｜缓存读写（细线分隔，无卡片）
├─ 主图表：细线、主次线分层、悬停标注；趋势 / 活跃度 / 请求 三视图
└─ 右侧栏（250px）：配额、最近请求、运行信息、提示
```

关键变化：
- **一张底、一张纸**：去掉卡片堆叠，信息靠细线、留白和字号层级组织；只有图表需要独立边界。
- **命中率成为 Hero**：它是 BYOK 的核心价值（缓存省钱），用一件大字号事实开场，而不是塞进五宫格。
- **每个数字紧跟一句人话**：如「缓存替您省了 $3.74」「有效 4 · 异常 0」，口径不用进 tooltip 才看到。
- **服务状态降为一行**：状态点 + 端口 + 内联文字操作，从 120px 高降到一行；错误时才展开为浅色提示条。
- **价值估算拆成两处**：总价值放 Hero 右侧，缓存读写拆分放 KPI 条，避免「$4.59」孤立。
- **侧栏承接次要状态**：配额、最近请求、运行信息、提示，不再挤在页脚和顶栏。

## 5. 令牌与迁移建议

令牌对照见 [design-system.html](preview/design-system.html)。落地路径：

1. **只改 `global.css` 的 `:root` 与 `[data-theme="dark"]` 两组变量**：色板、圆角（13 → 16/12/8）、字号阶梯、页面边距。组件不需要改结构。
2. **新增三个纯视觉组件**：`Sparkline.vue`（内联 SVG，几十行）、`FeatureCard` 变体（深色招牌卡）、胶囊导航样式（`.app-tabs` 的 CSS 重写）。

4. **其他页面跟随**：接入页改为「列表行」而非卡片堆叠；模型页保留列表 + 详情抽屉；设置页左侧分区导航。三者共用令牌即可，不需要整体重写。

需要单独覆盖的组件（结构类名不变）：

- `.mark`：品牌方块反相，深底上用暖白底 + 深色字。
- `.sw` / `.sw::after` / `.sw.on`：关闭态轨道 `#3b332a`，滑块暖白；开启态轨道用 `--accent`（注意 `.sw.on` 的覆盖必须写在 `.sw` 之后，否则会被压成灰色）。

## 6. 风险与未验证项

- 暗色令牌按截图目测调整，未做 WCAG 实测；`--ink-3` 在 `--paper` 上的对比度预计接近 4.5:1 下限，落地时需用工具复核。浅色 B 在 1024px 宽度下的重排效果未验证。
- 招牌卡与 sparkline 依赖真实时序数据；`homeMetricsReport` 的 `hour` 粒度是否始终可用，需要在实现前确认。
- 胶囊导航会增加顶栏高度约 6px，Wails 窗口最小高度需要同步调整。
- 预览为静态 HTML，交互（hover、切换、tooltip）仅示意，未接入 Vue 状态。

## 7. 决策记录

### 2026-11-18 · 页面结构定稿

| 页面 | 结论 | 理由 |
|------|------|------|
| 总览 | 第一轮 B 原稿结构 | 两个备选首屏都牺牲了数据阅读；B 原稿平衡最好 |
| 接入 | 左栏两组：对外提供服务 / 接入模型来源 | 这两类内容性质相反：共享入口与 Cursor 接入是本工具**对外**提供模型（给别人用）；订阅授权是**向内**接入模型来源，订阅本身不是 Codex / Grok 等 agent 的对接。混在一个列表里会让人误以为订阅是另一种客户端接入。右栏用编号分段（01 账号 / 02 同步到模型页 / 03 已同步模型）。来源顺序固定为 ChatGPT 订阅 / xAI 订阅 / Claude 订阅 / API 密钥：Claude 订阅放在第三位并标「暂不支持」，因为系统当前尚未开放接入，排在前两位会让人误以为可用 |
| 模型 | 左侧按来源导航 + 按来源分组的清单 | 列表类别用「来源」而非「厂商」：订阅是以来源为单位接入和失效的，凭据过期时按来源一眼定位；另外在工具栏保留「按厂商」切换。分组轴与接入页的模型来源一一对应，两个页面共用同一组名称 |
| 设置 | 分区导航 + 单列文档 | 设置是查阅而非任务；右栏在设置页没有行动价值，后续加分区不用重排 |
| 底色 | 02 宣纸·朱砂 | 截图观感最好；朱砂会与错误态撞色，错误态改为更深的砖红 `#8e2a1e` 并加粗 |

### 2026-11-18 · 订阅接入与模型页的联动

订阅（Claude / ChatGPT / xAI）在接入页登录后，模型自动同步进模型页，按来源分组。设计规则：

1. **自动发现、显式确认**：新模型以「新增」标记出现，默认停用，用户确认后再公开；不会静默改变 Cursor 里能看到的模型。
2. **下线不静默**：来源里消失的模型保留一条「已下线」，由用户决定删除还是继续显示。
3. **用户设置优先**：同步只增删模型条目，不覆盖用户改过的别名、开关、公开范围。
4. **来源失效不同步删除**：凭据过期或额度用尽时，来源标注失效，其下模型标「不可用」并从公开列表移除，但不删除——重新登录后自动恢复。
5. **单一归属**：每个模型只属于一个来源，避免同一模型两条记录、两套开关互相打架。
6. **名称统一**：「Claude 订阅 / ChatGPT 订阅 / xAI 订阅 / API 密钥」在接入页、模型页、总览页使用同一组名称与图标。

页面边距统一收到 28–32px（第一轮为 40px），密集页面的右栏宽度也相应压缩，避免大屏幕上留白过大显得空。模型页原先居中 840px 在宽屏下两侧各留出约 300px，改为左对齐、内容最大 1040px，与其余三页的左侧起点一致。

### 2026-11-18 · 方向定为 B · Paper

用户明确选择方向 B，判断依据是「人性化」：B 的纸感底色、留白、编辑式排版和克制用色让人愿意长时间停留；A 工具感过重；C 信息密度高但过于机械，读起来像监控面板。

这条判断应作为后续所有页面设计的取向，而不只是总览页的选型。

### 关于「B / C 作为主题切换」的判断：不建议

B 与 C 的差异是信息架构，不是配色皮肤：有没有卡片、KPI 怎么排、侧栏放在哪、字号层级怎么用，全都不同。把它做成主题意味着：

1. 每个页面的每个区块都要维护两套布局，组件里塞满风格条件分支；
2. 后续每个新功能都要双份设计、双份验证，两套都做不精；
3. 主题切换的语义被污染——用户以为只是换外观，实际整页结构会跳变。

行业里成熟应用的主题轴几乎都只有三类：亮 / 暗、强调色、密度。它们共享同一套 DOM 与层级。

### 保留的切换轴

- **亮 / 暗**：B 的亮色为默认皮肤，暗色是同结构的第二皮肤，只换令牌。
- **密度**（可选，后置）：若模型列表等密集页面在 B 下不够用，用「舒适 / 紧凑」密度开关解决，而不是换整套风格。
- 若未来仍想引入 C：以「同一 DOM 的皮肤变体」方式实现，而不是并行两套页面。

### B 的落地设计规则（从「人性化」推导）

1. **留白优先于填充**：页面边距 32–40px，区块间距 32px 起；卡片只用于需要独立边界的图表区。
2. **排版承担层级**：字号、字重、颜色三档对比足够，不再叠加边框、底色、阴影。
3. **数字克制**：等宽字体只用于数据本身；KPI 不超过 4 个，每个都带一句人话注释（「缓存替您省了 $3.74」）。
4. **文案精确**：状态用准确、可核验的词（运行中 / 已停止 / 错误），不做拟人化或口语化的包装；说明性文字只在用户需要理解代价或下一步时出现，错误信息必须给出下一步。
5. **状态轻量化**：服务状态用一行文字加小色点，不用带边框的胶囊堆。
6. **颜色纪律**：墨色为主，绿色只作唯一强调，琥珀与砖红只用于异常。
7. **每屏只回答一个问题**：用户打开这页最想知道什么，答案放在左上最显眼处。
8. **窄窗降级**（< 1100px）：Hero 数字缩小、右栏折叠到主列下方，不留横向滚动。
