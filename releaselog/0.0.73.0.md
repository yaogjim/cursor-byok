## 修复内容（检查点过早超时）

- 根因：`scheduleStreamTimer` 原先按 key 对 `TimerTokens[key]` 自增；clear/delete 删除键后，同 key 下次调度从 1 重新计数，尚未消费的旧 timer 事件可匹配新 pending 检查点，导致新检查点被旧事件立即标记 timeout 或跳过。
- `internal/backend/forwarder/types.go`：`ActiveStream` 新增 `NextTimerToken`（同一流内递增；清理或重建 `TimerTokens` 时不得重置）。
- `internal/backend/forwarder/actor.go`：`scheduleStreamTimer` 在既有锁内递增 `NextTimerToken` 并赋值给 `TimerTokens[key]`；clear 仍删除键，不积累已清理键。生产差异仅 +3/−2 与 +1 字段。
- 保持 5 秒超时、ACK 齐全才发布、真正超时的降级语义全部不变。
