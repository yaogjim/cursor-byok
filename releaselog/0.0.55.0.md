# Gateway-byok v0.0.55.0

本版本完成 Rule 存储 P0 安全加固、docs index 恢复闭环与 managed Codex 缓存亲和基础阶段；Rule 远端同步保持默认纯本地零上传，Codex 亲和只完成协议接线，不宣称缓存收益。

## Rule 持久化 P0 加固

- 私有权限：Rule 根目录与文件在 Unix 收紧为目录 `0700`、文件 `0600`；Windows 使用最小平台 helper（拒绝 reparse point，受保护 DACL 仅当前用户与 SYSTEM 完全访问）。迁移只处理 legacy 根目录中的规范直接子项，symlink、非普通文件拒绝，已存在目标不覆盖内容但立即收紧权限，config 与 rules 均完整迁移后才删除 legacy 来源。
- 原子写与提交语义：Rule 与 docs index 持久化采用同目录唯一临时文件、flush/sync、原子 rename 与失败清理；rename 成功即视为外部提交成功，rename 后父目录 sync 失败仍保留已提交语义，不向调用方返回会诱发重复写入的 durability error。故障注入通过 per-store `persistFileOps`，不是进程级全局 hook。
- 有界容量：单 Rule 128 KiB、最多 128 个 Rule、磁盘正文总量 1 MiB、单次 Prompt 注入 256 KiB，全部按字节计算不截断；既有超限文件保留在磁盘但隔离并返回明确诊断，不进入 Prompt。扫描先按大小/数量/累计大小拒绝，再用 `io.LimitReader` 有界读取。

## docs index 来源隔离与恢复闭环

- Rule `.md` 文件是 Rule `id + content` 事实源；docs index 同时承载 Rule 投影、上传文档与 `additional_docs`，不是 Rule 事实源。
- reconciliation 只幂等重建/删除 Rule 投影，必须保留上传文档和其他非 Rule 记录；损坏 index 先隔离，再恢复可从有效 Rule 文件重建的投影，无法恢复的上传记录不伪造。
- Rule CRUD 成功表示事实源已提交；索引失败设置内部 dirty 并触发后续 reconciliation，不回滚 Rule。dirty 未修复前 Rule Prompt 继续使用有效 Rule 文件，Rule 来源 docs query fail closed，避免返回已删除的陈旧正文。
- copy-on-write 保存：保存失败不能把未落盘状态留在内存；补文件/父目录同步、私有目录权限、索引大小/记录数/正文总量上限。

## managed Codex 缓存亲和基础

- 稳定账号身份：优先使用持久账号记录的 `AccountID`；token 指纹 fallback、邮箱和 `ChatGPTAccountID` 不作为亲和键，不稳定身份不启用亲和。
- 独立私密安装密钥：应用私有订阅目录保存 32 字节 `codex-affinity.key`，原子写、`0600`、拒绝 symlink 与非法长度，不复用 observability key，不进入配置、Wails、日志或导出。
- HMAC 域分离派生：`prompt_cache_key`、`session-id`、`thread-id` 在同一稳定账号 × 同一 conversation 稳定且互不相同；`x-client-request-id` 额外绑定逻辑 `ModelCallID`，同一 HTTP retry 保持不变，不同逻辑请求唯一。401 刷新且稳定账号不变时保持；quota 轮换账号后重新分区。
- 精确注入边界：仅对 `credentialSource=codex` 且精确 ChatGPT Codex Responses 端点注入；调用方 body/header 同名值先删除或覆盖；Authorization、originator、ChatGPT-Account-Id 与三个亲和 header 为保留 header，custom headers 不能覆盖；`previous_response_id` 继续无条件删除，`store=false` 不变；static OpenAI、Grok 和其他兼容端点完全保持现状。
- 内部实验 profile `control | prompt_key | full`，未知值回到 `control`；先只验证 `prompt_key`，再开启 `full`。亲和请求体注入已移到请求工件记录之前，工件 `body_byte_len` 与实际发送一致且不记录亲和值。
