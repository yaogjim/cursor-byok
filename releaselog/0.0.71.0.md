# Gateway-byok v0.0.71.0

本版本完成「gateway-duo 双渠道移植：Cursor 官方与 BYOK 共存」（需求锚点：工作决策基线 §10.17；设计锚点：系统架构 §18「gateway-duo 合并」D1–D4）：以 `gateway@4e4f2f1` 为基底移植 `gateway-duo@18ef0e2` 相对共同祖先 `334f538` 的双渠道功能，保留目标分支现有订阅、模型解析/变体/备用渠道、CLI 占位、API 与代理能力。交付状态 `verified-partial`：internal 全量测试、五包 race、相关 vet 与 Host 级契约验证通过；真实 Cursor 登录、桌面/CLI 来源显示、官方/Auto 对话及真实 OAuth 刷新的实机验收待完成。

## 模型与身份分流（D1/D2/D4）

- 官方身份定义为非空且非 LocalRelayToken 的 Bearer；本地渠道 ID（含变体、唯一旧渠道 ID）优先命中走现有 forwarder 管线，其余有官方身份的请求（含 auto/fast/default、空初始选模）原样透传官方；纯本地身份沿用现有本地解析与默认行为，未知或歧义报错不猜。
- 复用内存 `AgentSessionStore` 实现 request_id 级渠道记忆：首次 Local/Official 决策保持，后续工具/心跳/取消按原请求渠道继续，不因无模型字段重新选默认；RunSSE 先到等待 BidiAppend，取消清理等待。
- 修复路由存储跨配置重建分裂：`AgentSessionStore` 提升到 Host 生命周期，在既有 `runMu` 保护下只初始化一次，两处理器共用；旧 mux 的等待流与新 mux 的上行共享路由事实。
- 修复 OAuth 接线缺陷：`Routing.Mode=upstream` 此前绕过只挂在 Local 上的 OAuth 分流器，把本地占位 refresh 发给官方；现 `/oauth/token` 的 Upstream 分支挂同一身份分流处理器，local/upstream 两模式均通过 Host 级测试（本地零官方命中、真实刷新保留请求体/身份并返回官方响应）。
- state.vscdb 事务内保留已有非空官方身份整组字段，仅缺失/空时注入本地身份；存量占位身份保留至用户正常登录，不自动删除身份。真实 OAuth 刷新透传，仅已知本地占位 refresh token 使用模拟响应。MITM 保留 CONNECT 范围，解密后未分类路径透明回源。

## 目录合并与来源标注（D3）

- 官方目录与本地目录合并：官方原顺序在前、本地配置顺序在后；按 ID 去重，同 ID 本地优先，同名不同 ID 并列。官方目录失败仍返回本地可选项，但不把本地模型推荐成官方默认，官方默认请求失败不悄悄走本地。
- 桌面/CLI 目录、默认模型详情与变体显示名追加 `[官方]`/`[BYOK]` 后缀；模型 ID、磁盘配置名、hash、调用参数一律不改；纯本地目录同样标注来源。
- 本地 CLI Credentials 只重建 `apiKey=cursor-byok-local` 的既有无秘密占位；官方 Credentials 不注入该占位。
