# Gateway-byok v0.0.72.1

本版本完成「OpenAI Responses 流式 `[DONE]` 兜底收口修复」：修复 Responses 流仅收到 `[DONE]`（缺 `response.completed`）时两条缺陷路径——普通成功收尾不发 `TurnFinished` 导致客户端挂起，以及带未收口 `function_call` 参数的截断流被误判为普通成功。交付状态 `verified-partial`：定向回归测试通过；真实上游实机验收待后续窗口。

## 根因

- `streamResponses` 的 `[DONE]` 兜底路径未仿照 Chat 路径补发 `TurnFinished`：缺 `response.completed` 的正常文本流收尾时 `turnFinishedPending` 仍为 false，客户端等待终态事件直到超时。
- `completeTool` 收到非法 JSON 参数时静默跳过（`return nil`），`[DONE]` 兜底路径不再复查 `tools` 累加器：参数未收口（截断）的 `function_call` 流被当作普通成功收尾，客户端拿到半截参数继续执行。

## 修复内容

- `openai.go`/`streamResponses`：`completeTool` 参数不完整时返回 `newStreamTruncatedError("openai", nil)` fail-closed，不再静默跳过。
- `[DONE]` 兜底路径先复查全部 `tools` 累加器：任一参数未收口即按流截断 fail；全部收口且尚未发 `TurnFinished` 时兜底补发（无工具普通成功默认 `stop`，已发工具完成时保留空值交由 `effectiveFinishReason` 归一为 `tool_calls`）。
- 正常 `response.completed` 终态路径行为不变；Chat 路径不变。

## 回归测试（先红后绿）

- `TestOpenAIResponsesDoneWithoutCompletedEmitsTurnFinished`：仅 `output_text.delta` + `[DONE]`（无 `response.completed`）仍发出 1 次 `TurnFinished` 且 finish reason 为 `stop`。
- `TestOpenAIResponsesDoneWithIncompleteFunctionCallTruncates`：`function_call` 参数半截（`{"path":`）后直接 `[DONE]` 判定为流截断（`missing completion marker`），不发 `ToolLikeCompleted`/`TurnFinished`。

- 证据边界：Host 本地模拟上游证明 `[DONE]` 兜底两条路径行为；真实上游截断/正常混合实机验收待另行确认窗口。
