# Gateway-byok v0.0.56.0

本版本完成 Provider 历史净化：跨 Provider/端点/凭据身份重放旧会话时，不再把不可验证的 opaque reasoning 与 Responses item 元数据发给目标 Provider，从根因修复长会话在 Codex 与第三方 Responses 之间切换后出现的 HTTP 400（如 "encrypted content could not be verified"）。同源续聊能力不回退。

## 目标感知历史净化

- 新增最小来源身份 `ReasoningOrigin`（provider、规范化 endpoint、credential source、账号身份、模型），随 thinking/tool 事件产出、随 history `assistant_text`/`tool_call`/`tool_result` 持久化（`omitempty`，旧会话可读），发送边界按当前实际渠道与凭据重新计算目标身份。
- 身份判定：managed 凭据使用稳定账号 ID；static API key 使用 SHA-256 指纹（不落明文）；endpoint 身份包含非默认端口与规范化 base path，query/fragment/尾斜线不参与；ChatGPT Codex 官方端点保持 `chatgpt_codex` 稳定标识。
- 跨身份或旧数据缺少来源身份（fail-closed）时成组剥离：reasoning signature 及来源、OpenAI Responses reasoning ID/status/summary、工具调用上的 Responses item/call/status。
- 保留可移植语义：assistant 可见文本、可见 reasoning 文本、本地工具调用 ID、工具名与参数、tool result 配对；现有 merge、悬空调用修剪与尾部 prefill 修剪行为不变。
- 旧 Anthropic 同源 thinking signature 保留兼容路径；旧 OpenAI Responses 数据缺少来源身份时 fail-closed 剥离，不再向需要校验的目标重放。
- 修复 provider done 先清零来源身份导致落盘丢失的问题：成功、失败、continuation/fuse 各 flush 路径均使用清零前快照；工具完成事件先采纳来源身份再 flush 文本。

## Provider 400 诊断摘要

- 将 `HTTPStatusError` 既有 8 KiB 限长读取、JSON message 提取与 `audit.SanitizeMetadataText` 脱敏结果投影到 `provider_stream_finished` 与终态诊断：新字段 `provider_error_summary`、`provider_error_summary_type`，缺省 `not_recorded`。
- 不记录原始 body、headers、URL、API key 或账号信息；错误分类与 400 不可重试语义不变。
- `SanitizeMetadataText` 补充无标签凭据脱敏：`sk-`/`sk-proj-`/`sk-ant-` 与 JWT 三段格式替换为 `[REDACTED]`。

## 编码请求体上限预检

- OpenAI 与 Anthropic 在最终 JSON 编码后、创建 HTTP 请求前检查 32 MiB 单一包级上限；超限返回 typed `RequestBuildError`（仅含 actual/limit 字节数，不含正文），零 HTTP attempt、不重试、不 fallback。
- 构建失败统一 `MarkRequestBuildFailed`，fallback suppression 原因记录为 `request_build` 而非 `no_http_attempt`。
- 现有 token 压缩判定保持不变；本项只兜底 token 估算无法覆盖的 JSON/opaque 元数据膨胀。
