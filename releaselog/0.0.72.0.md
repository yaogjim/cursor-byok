# Gateway-byok v0.0.72.0

本版本完成「日志增强与异常保留」：在现有日志链内补齐异常事件独立保留、总额度控制、诊断内容分级与离线分析消费，并完成两轮独立复核修复。交付状态 `verified-partial`：隔离 HOME 下定向测试、race、vet、前端构建与配置投影全部通过；桌面桥接与真实运行验收待后续窗口。

## 异常独立保留与总额控制

- WARN/ERROR 安全副本写入 `logs/diagnostics/diagnostics-*.jsonl`，复用现有 `RotatingFile`；在现有总额度 B 内预留 `D=floor(B/8)`，普通分区使用 `B-D`，互不借用，期限继承现有 `retentionDays`。
- 队列保留单个 FIFO 与原 `QueueSize`：普通入队不得占用 `max(1, QueueSize/8)` 异常预留；异常队列丢弃另计入 `DiagnosticDropped`，off 不启用预留。
- 普通分区淘汰顺序：过期受管日志 → closed/full trace → closed/basic trace 与旧 app 分片合并的按时间单层（同时间按路径裁决）；活跃分片、open trace、未知/损坏 manifest、symlink 及归属不明文件受保护。
- 诊断分区在共享预算锁内按磁盘实际用量准入；写满 D 时丢弃该记录并经既有状态链报告 `diagnostic_reserve_exceeded`，业务继续。
- app 日志读取配置后才落盘并进入普通预算；配置重载失败恢复旧预算；轮转按容量或期限触发。

## 诊断内容与分级

- 重试且明确继续恢复的 attempt 为 WARN，最终失败/不完整为 ERROR；attempt 异常数量与 `model_call_final` 唯一调用终态分别统计。
- checkpoint 增加 dispatch/ACK/timeout/cancel/unmatched 安全元数据（专用 `checkpoint_result`，双端白名单脱敏，不记录 blob key）；拒绝 ACK 只记录固定类别。
- `FetchUpstream` 补请求构造、执行、读取及大小限制的真实失败阶段记录；请求/响应/返回错误行为不变。
- 摘要经生产端与离线消费端的类型、长度（512 runes）及敏感内容限制；v1/v2 读取路径保留，缺失新字段显示 unknown/not_recorded。

## 分析器与消费链

- loader 识别 diagnostics 目录与直接文件；同一 dataset 按 `(app_session_id, sequence)` 合并副本，优先保留 full trace 的 `payload_ref`，真实冲突报错，不猜测旧身份。
- 安全字段贯通装载、查询、事件详情、报告与诊断包导出（含 severity 投影）；仅有异常分片时明确提示材料不完整，不计算全量成功率。
- 设置页复用现有采集状态区域展示异常保留与降级状态；分析器详情展示安全字段。

## 复核修复（两轮独立 review）

- manifest 真正拒绝超额写入；临时文件失败清理与计量失效重扫；关闭失败可查询且返回错误。
- 异常写满先回收封存分片、必要时封存自己的分片后再准入，保护其他写入器的活跃分片；超大单条不先删历史。
- 普通分区回收把 closed/basic trace 与旧 app 分片合并为单一按时间层级；诊断分区改为共享预算锁内按磁盘实际用量准入；删除死代码 `diagnosticUsageBytes`，锁序 sink → budget → RotatingFile 无反转。
