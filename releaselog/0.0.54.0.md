# Gateway-byok v0.0.54.0

本版本完成 Subagent 安全自动重调度的基础设施（attempt 持久化与 fencing、typed failure 基础、attempt 级观测），功能保持**默认关闭**；在线自动重调度与“自动恢复已解决”声明仍按安全门 blocked。

- Attempt 持久化与 fencing：`subagent_run_id` 继续作为一次逻辑 Task 的稳定 ID，每次实际派发新增独立 `attempt_id` / `attempt_no`；`PrepareTerminalForAttempt` 在同一 run 锁内校验提交者仍是 current attempt，stale 结果不能创建或覆盖 `result.json`。
- 幂等提交隔离：terminal 按 attempt 提交，旧 attempt 晚到的 success/error 被隔离丢弃，不能覆盖新状态；一个 logical run 仍最多一次 parent handoff。
- Typed failure 与 policy 基础：新增 `SubagentFailureRegistry` 与 `SubagentRescheduleSettings`（首版为内存实现、未接线运行时）；policy 只处理 typed 状态，绝不解析错误文本，不在运行时代码中匹配 `stream_decode` / `stream_idle_timeout` 字符串。
- 配置与前端：新增顶层 `subagentReschedule.enabled`，默认 `false`，配置缺失保持关闭；前端设置页按既有 config projection 模式补齐加载/保存/脏状态，并显示开关；开关保留展示但固定 inert，文案明确等待稳定 typed failure fixture。
- 观测贯通：`Correlation` 与事件顶层新增可选 `subagent_attempt_id` / `subagent_attempt_no`，贯通 normalize、merge、apply、child span 与 debug recorder；`tools/log-analyzer` 同步保留 attempt 字段，只扩展可选字段，不改变既有 schema 语义。
- 安全边界：稳定 `run_id` + 独立 `attempt_id`，不冒充恢复同一远程 child；不修改 Cursor proto；store 因隐私约束不保存 prompt/result 正文。

范围与状态：

- 自动重调度与自动恢复**未达生产可用**：真实 Cursor 链路尚无把 child provider typed `stream_decode` / `stream_idle_timeout` 稳定关联到 parent Task physical attempt 的完整生产链路；在线 relaunch、真实灰度与“自动恢复已解决”声明全部按安全门 blocked。默认关闭、显式授权、可回滚。
- 保守行为说明：配置默认关闭暂不约束运行时，现有全部 Task 被无条件接入 attempt 持久化与 fencing，作为只读安全基础（代码注释已声明，不构成自动重派）。

验证：`go test ./internal/backend/...`、`go vet`、`go test -race ./internal/backend/forwarder ./internal/observability`、`go test -count=20 ./internal/backend/forwarder -run 'Test.*(Concurrent|LateResult|Reschedule)'`、前端 `test-config-projection.mjs` 与 `npm run build` 均通过；提交前按指示不再运行。未编译、未构建或发布安装包。
