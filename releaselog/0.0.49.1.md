# 0.0.49.1 版本更新说明

发布日期：2026-08-21

## 版本概览

本版本完成 P1 子代理持久交接与 Provider fallback 能力建设，并收紧 Provider 断连终态、观测关联和敏感数据边界。Provider fallback 默认关闭；子代理恢复保证限定为已生成终态的持久化与幂等父会话交接，不承诺 Backend 崩溃后从子代理执行点自动续跑。

## 1. 子代理身份与终态合同

- 为每次 Task 派发生成稳定的 `subagent_run_id`。
- 贯通 root conversation、parent conversation、parent tool call、parent model call、child conversation、agent、model call 和 attempt 等关联字段。
- 增加结构化终态分类：`succeeded`、`canceled`、`timeout`、`provider_error`、`tool_error`、`parent_unavailable`、`truncated` 和 `protocol_error`。
- 采用首个持久化终态获胜策略；重复或冲突 completion 不覆盖已确认终态。
- 继续使用现有生成 proto 字段，没有修改公共 proto 定义。

## 2. Durable Handoff 与重启恢复

- 新增版本化 `SubagentRunStore`，在 `historyRoot/_subagents/<run_id>/` 持久化 `run.json` 和 `result.json`。
- 使用 schema version、checksum、原子临时文件替换、文件 fsync、目录 fsync 和受限文件权限保护持久记录。
- 交接顺序固定为：
  1. 持久化 `terminal_prepared` 与 durable result。
  2. 在父会话锁内幂等追加 `tool_result` 和关联 metadata。
  3. 标记 `parent_committed`。
  4. 在线 checkpoint 成功发布后标记 `acknowledged`。
- 父会话结果使用稳定幂等键；重复 completion、重复恢复和并发 replay 不会重复写入父会话。
- 启动扫描可恢复 `result.json` 已落盘但 `run.json` 尚未更新的崩溃窗口。
- Backend 重启时，未终结子代理进入 `awaiting_client_resume`，不会被 Backend 自动重派。
- 父会话身份缺失或持久会话不存在时保留 durable result，并进入 `awaiting_parent_resume`；恢复逻辑不会创建仅含 `tool_result` 的孤立父会话。
- checksum 错误、版本不兼容和未知 run 状态会隔离到 `_corrupt/`，不会被静默忽略。
- 同一 `historyRoot` 仍采用单活 Backend 写入约束；本版本没有引入跨进程 OS 文件锁。

## 3. Provider Fallback

- 新增默认关闭的 `providerFallback` 配置和显式有序候选链。
- 后端与前端共同校验空候选、重复、自引用、悬空引用、跨 adapter 非法引用等错误配置。
- 主渠道和候选渠道共享最多 5 次 HTTP attempt 与 8 秒退避等待预算。
- 只有在零原始响应字节、零 model event、零工具进度和零下游副作用时才允许切换渠道。
- 任意原始流字节、model event、上下文取消、请求构建失败、非重试错误或不安全自定义请求体都会阻断 fallback。
- 对 Provider family、工具 schema、图片、opaque reasoning/tool state、context window 和输出容量执行兼容性门禁。
- 不兼容候选会被跳过，但不会改变最后一个实际尝试渠道的兼容性基准。
- `fallback_to` 与工件后缀现在按下一个真正兼容的候选计算；剩余候选全部不兼容时，最后实际渠道保留原始 `model_call_id`。
- 整条 fallback chain 保持同一业务 `model_call_id` 和唯一最终业务终态。

## 4. 前端配置

- 在模型配置界面增加 Provider fallback 开关和有序候选渠道编辑能力。
- 默认保持关闭，避免升级后自动改变 Provider、费用或模型语义。
- 增加费用、隐私边界、模型语义和工具兼容性提示。
- 配置投影、导入导出和多语言目录支持 `providerFallback`。

## 5. Provider 断连与共享预算

- OpenAI Chat、OpenAI Responses 和 Anthropic 流继续严格要求各自协议完成标记。
- 首输出前的同渠道 retry 与跨渠道 fallback 使用统一 typed safety 状态和共享预算。
- 实际退避时长精确扣减共享等待预算。
- 产生任意原始字节或下游输出后禁止 retry/fallback，避免拼接不同响应或重复工具副作用。

## 6. 观测关联与隐私保护

- 观测合同补充 root/parent/subagent/child/agent 等关联字段，并防止空字段覆盖已知值。
- Provider 请求工件不再记录请求正文、消息正文或内容预览。
- Provider 响应工件只记录受控长度等元数据，不写入 raw chunk。
- Provider URL 写入前移除查询参数和潜在凭证。
- Authorization、Cookie、API key、敏感 header、原始请求体和响应正文不会进入生产观测工件。
- 子代理 prompt、result 和控制消息正文不会进入 debug/observability 日志；恢复所需正文仅保存在专用 durable result 存储中。
- compaction、commit message 和子代理错误摘要改用结构化类别或受控摘要，不直接持久化任意原始错误文本。

## 7. Checkpoint 与审查修复

- 子代理 `acknowledged` 只在 checkpoint blob 完成且 checkpoint 成功发布后写入。
- checkpoint 尚未返回或发布失败时保持 `parent_committed`，不提前确认，也不回滚已提交父会话结果。
- 同 Provider 的自定义原始请求体也会阻断 fallback，避免无法证明语义等价时切换 endpoint/model。
- 缺失父会话、未知 run 状态和 fallback 实际最终渠道均新增回归测试。

## 已知限制

- Provider fallback 默认关闭，只有用户显式配置候选链后才会生效。
