# Gateway-byok v0.0.72.2

本版本完成「模型切换 imported replay Blob 引用兼容修复」：修复同一 Agent 会话先用普通模型完成任务、再切换高级模型分析时，导入 `conversation_state` 报 `decode imported replay messages: invalid character '>'/'h' looking for beginning of value` 并返回 500 的问题。交付状态 `verified-partial`：定向回归测试通过；真实桌面模型切换实机验收待后续窗口。

## 根因

- Cursor 本机 Agent runtime 的 `fromConversationStateStructure` 对 `rootPromptMessagesJson` 中每个元素调用 `getBlob` 再反序列化为 `coreMessage`，即该字段在当前客户端承载 32 字节内容寻址 Blob ID。
- 网关 `importedConversationStateModelMessagesWithBlobs` 原先无条件把这些元素交给 `DecodeReplayMessages` 做 JSON 解码，随机 SHA-256 首字节被报告为 `>`、`h` 等非法 JSON 字符。模型切换/会话 fork 首次导入 `conversation_state` 时触发。

## 修复内容

- `internal/backend/forwarder/token_usage.go`：仅当 `root_prompt_messages_json` 的全部非空元素均为 32 字节 Blob 引用且 `turns` 非空时，跳过旧 JSON replay 分支并复用既有 Blob-aware turns 导入路径。
- 普通非 JSON、JSON/Blob 混合内容，以及没有 turns 可回退的 Blob 引用仍保持报错，不静默丢失历史。
- 未新增依赖、配置、协议抽象或迁移逻辑。

## 回归测试（先红后绿）

- `TestImportedConversationStateFallsBackFromBlobRootPromptsToTurns`：Blob root prompts 回退 turns 后恢复父会话 user/assistant 两条消息；修复前稳定失败并复现 `invalid character '\u008b'` 同型错误。
- `TestImportedConversationStateRejectsMalformedNonBlobRootPrompt`：普通非法 replay 数据继续拒绝。
- `TestImportedConversationStateRejectsBlobRootPromptWithoutTurnFallback`：无 turns 回退的 Blob 引用继续拒绝，不静默丢历史。
